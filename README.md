# Dental Care 24

אתר React בעברית וב־RTL למרפאת דנטל קר 24. קוד המקור זמין לשינוי והפצה ברישיון MIT; לוגואים ותמונות מטופלים אינם כלולים ברישיון הקוד.

## מה נבנה

- עמוד בית מעוצב, צילום קונספט ייעודי, טיפוגרפיה מקומית ותנועה מותאמת לגלילה.
- אנימציית Canvas: שן מחלקיקים מתפזרת למסלול וחוזרת לצורה המקורית, עם תגובה לסמן והפחתת תנועה לפי העדפות מערכת.
- חמישה עמודי טיפול, שאלות ותשובות, יצירת קשר ושני סניפים עם ניווט למפות.
- סטודיו הדמיה: בחירת טיפול, 1–3 תמונות, תצוגה מקדימה, מחיקה, הסכמה, תמונה לכל זווית, השוואה ושמירה.
- שרת Express עם חיבור ל־OpenAI Images Edits ול־Resend. המפתחות נשארים בשרת.
- הגבלת קבצים ופניות, בדיקת תמונות בפועל, הסרת EXIF, מניעת כפילויות והגבלת תקציב תמונות בתהליך שרת יחיד.
- מסמכי פרטיות ונגישות, עיצוב מותאם למובייל וניווט מקלדת.

## הפעלה מקומית

נדרש Node.js 22 ומעלה.

```bash
npm install
cp .env.example .env  # רק אם עדיין אין .env
npm run dev
```

האתר: http://127.0.0.1:5173. השרת: http://127.0.0.1:3001.

ללא מפתחות ניתן לצפות באתר, לעבור בין השלבים ולהעלות תמונות לתצוגה מקדימה בדפדפן. אין שליחת פניות או יצירת תמונות מדומה.

## הפעלת AI ומייל

ממלאים **במחשב או במנהל הסודות של האחסון, ולא בצ'אט**:

- `OPENAI_API_KEY`: חשבון API עם הרשאת יצירת תמונות וחיוב פעיל. מודל ברירת המחדל הוא `gpt-image-2.5-sunburst`; ניתן לשנות ב־`OPENAI_IMAGE_MODEL` למודל התומך ב־Images Edits ובפרמטרים שבשרת.
- `RESEND_API_KEY`: מפתח Resend.
- `MAIL_FROM`: כתובת שולח מדומיין שאומת ב־Resend. כתובת Gmail של הנמען אינה כתובת שולח מאומתת.
- `LEAD_EMAIL`: כבר מוגדר `yosef2112@gmail.com`.

לאחר שינוי מפעילים מחדש את השרת. לא בוצעה בדיקה בתשלום מול OpenAI ולא נשלח מייל אמיתי במהלך הפיתוח. הבדיקות האוטומטיות משתמשות בספקים מדומים.

פרטי הסניפים והטלפונים נמצאים ב־`shared/clinic.json`. המספר הראשון הוגדר כוואטסאפ ראשי; יש לאמת שזה המספר הרצוי. לא נוצר מאגר מטופלים או חשבונות משתמשים.

## בדיקות ובנייה

```bash
npm test
npm run build
npm start
```

במצב production השרת מגיש את קבצי React ואת ה־API מאותו מקור. פורט ברירת מחדל 3001. בהפעלת קונטיינר הגדירו `HOST=0.0.0.0` והשתמשו ב־HTTPS דרך reverse proxy.

## לפני פתיחה לציבור

1. להגדיר `PUBLIC_ORIGIN` לדומיין המדויק (ללא slash בסוף), `TURNSTILE_SITE_KEY` ו־`TURNSTILE_SECRET_KEY`, ולהתאים `TRUST_PROXY_HOPS` לטופולוגיית האחסון — לא להגדיר trust proxy באופן גורף.
2. להשלים עם המרפאה את הזהות המשפטית ותקופת שמירת הפניות במייל, לעבור על הטקסט הרפואי ומדיניות הפרטיות, ורק אז להגדיר `PRIVACY_REVIEWED=true`.
3. לבצע בדיקת קצה לקצה עם תמונת בדיקה והסכמה: קבלת המייל הראשוני, יצירת תמונה, קבלת מייל תוצאה, והשוואה/הורדה. ב־production הטפסים חסומים עד השלמת ההגדרות לעיל.
4. להגדיר מגבלת הוצאות אצל ספק ה־AI. המכסה המקומית (`MAX_DAILY_IMAGES`, ברירת מחדל 30) נשמרת בזיכרון ומתאפסת בהפעלה מחדש; היא אינה בקרת תקציב קשיחה לפריסה עם מספר מופעים.
5. הגדרת זמן בקשה של לפחות 240 שניות בפרוקסי. בייצור עתיר תעבורה יש להחליף את הבקשה הסינכרונית בתור משימות ולרכז מכסות ומפתחות idempotency ב־Redis/DB.
6. בדיקת נגישות מקצועית ובדיקת איכות ההדמיות בפנים וזוויות שונות. לא ניתן להבטיח זהות מושלמת או תוצאה רפואית מההדמיה.

### זרימת הנתונים

התמונות נבדקות, מוקטנות ומוסרות מהן מטא־נתונים → מייל עם פרטי הפנייה והתמונות למרפאה → בקשת עריכת תמונה לכל זווית → תוצאות לדפדפן ומייל נוסף למרפאה. כשל בשליחה הראשונית עוצר את יצירת ההדמיה. כשל בשליחת התוצאה מוצג למשתמש, והתמונה נשארת זמינה לשמירה בדפדפן.

השרת אינו כותב תמונות לדיסק. תוצאות שמורות זמנית בזיכרון עד 15 דקות לצורך מניעת חיוב כפול; עד 30 פניות במטמון. המיילים עצמם נשארים אצל ספק המייל ובתיבת המרפאה. כשל יצירה עשוי עדיין להיות מחויב אצל ספק ה־AI; אין retry אוטומטי של יצירה בתשלום.

## תוכן ומיתוג

הטלפונים, הכתובות, המייל והלוגואים התקבלו מהלקוח. צילום הקונספט נוצר ב־ImageGen; הוא אינו מטופלת ואינו תוצאת טיפול. אין באתר המלצות מומצאות, ספירה לאחור או נתוני הצלחה בלתי מאומתים. פרטי המקורות, ההשראה והתוכן שהושאר לאישור ב־`docs/content-and-assets.md`.
